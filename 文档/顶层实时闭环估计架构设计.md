# 顶层实时闭环估计架构设计（视觉-运动融合）

> 目标：在顶层（TopLevel）内**实时读取电控（dSPACE）机械关节角反馈**，结合**物理结构数据**（运动学/末端几何）与**相机返回数据**（YOLO+白点 6DoF 位姿），**在线估计目标的真实位置与姿态角**。
> 状态：**设计文档**（未实现）。可行性已确认——这是工业机械臂"视觉伺服 + 手眼标定 + 状态估计"的标准做法。

---

## 1. 为什么可行（第一性原理）

目标定位精度受三处误差影响：**视觉检测误差、手眼标定误差、运动学/执行误差**。当前系统这三个误差源都"开环硬扛"：
- 手眼标定缺失（`projectTo2D` 用相机系直接当基座系）
- 无执行反馈（规划→下发→不管）

**核心洞察**：电控的**关节角编码器反馈是免费的"真值锚"**——它把"规划假设"与"实际运动"连起来：
```
真实末端位姿 = FK(真实关节角)      ← 编码器反馈驱动，不受执行误差影响
目标基座系位姿 = T_base_cam × 目标相机系位姿   ← 相机观测 + 手眼变换
两个等式在机械臂运动的多帧观测下联立 → 可在线估计 T_base_cam（手眼标定）与目标状态
```

**这就是闭环**：即使静态标定板标定做不了，**在线手眼标定**（运动多帧观测）也能收敛 T_base_cam；即使运动学有误差，**反馈闭环**也能校正。

## 3. 模块设计

### 3.1 电控上行接口（P0 缺口 #4 的一部分）
- **下行已有**：`exportMotorCmd`（q_seq/t_seq/gripper_seq）
- **上行新增**：`readMotorState` 接口——dSPACE 实时循环按节拍发布：
  - `θ_real [1×6]`（编码器关节角，rad）
  - `gripper_state`（夹爪开/合/到位）
  - `status`（RUNNING/COMPLETED/FAILED/ESTOP）
  - `timestamp`（dSPACE 节拍时间）
- 传输通道：文件桥（与下行对称，`.mat`/JSON）或共享内存——**由电控侧实现，软件侧定义协议**（扩展《电控对接说明》）

### 3.2 正运动学 + 末端几何
- `planarFK_L` 已有（关节角 → 末端位姿）
- **新增**：相机安装位姿 `T_ee_cam`（末端→相机刚体变换——由末端几何 P0#3 提供：相机在末端链上的位置/朝向）
- 则 `T_base_cam = T_base_ee × T_ee_cam`

### 3.3 手眼在线估计（关键新增）
- **2D 平面任务简化**（验收为地面平面）：T_base_cam 退化为 2D 刚性变换 `(t_x, t_y, θ)`——**3 个未知数**
- 观测方程：`X_base = R(θ)·x_cam + t`——每帧目标观测给 2 个方程（x,y）——**2 帧不同姿态即超定**——最小二乘/递推即可收敛
- **可观测性**：机械臂需运动到不同姿态（平移/旋转均产生新约束）——**任务执行过程天然提供**
- **递推实现**：递推最小二乘（RLS）或滑动窗口 SVD（Procrustes 对齐多帧 {x_cam_i, X_base_i}）
- 3D 演进：SE(3) 手眼标定（AX=XB，如 Tsai-Lenz），已留接口（chessboard_calibration 代码可复用）

### 3.4 目标状态估计
- 多帧融合：Kalman 滤波（状态 = 目标位置+姿态角+速度，观测 = 相机位姿）
- 收益：**抖动抑制**（视觉噪声）、**遮挡鲁棒**（预测填补）、**平滑目标位姿**（触发任务的位姿更稳）

### 3.5 任务触发与执行
- 用估计的目标位姿（而非单帧）触发 `taskExecute`/规划——**位姿更准 → 夹取/放置更稳**
- 执行中继续读反馈 → 完成后回传状态 → 顶层循环下一任务

## 4. 难点与前提

| 难点 | 说明 | 对策 |
|---|---|---|
| dSPACE 上行通道 | 需电控侧配合发布关节角反馈 | 定义协议（扩展《电控对接说明》）；无硬件时用**仿真反馈**（mock：关节角=规划轨迹+噪声）联调 |
| 时间同步 | 相机 ~30fps vs 电控 kHz——帧间时延 | 时间戳对齐 + 插值；Kalman 处理异步观测 |
| 手眼可观测性 | 机械臂不动时 T_base_cam 不可观 | 任务执行过程自然多姿态；必要时加"标定运动"指令 |
| 运动学残差 | FK 本身有误差（关节偏置/杆长） | 反馈闭环 + 在线运动学参数辨识（后续 P2） |
| 2D→3D 演进 | 验收为平面；3D 场景需 SE(3) 估计 | 接口预留（维度参数化） |

## 5. 落地路径

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **S1 顶层骨架 + mock 反馈** | `runTopLevel.m` 常驻循环（读反馈→FK→观测→估计→任务）；电控反馈用仿真 mock（规划轨迹+噪声） | 无硬件 |
| **S2 手眼在线估计（2D）** | RLS/SVD 估计 T_base_cam；收敛性验证（合成数据） | S1 |
| **S3 目标状态估计** | Kalman 融合多帧；抖动/遮挡测试 | S2 |
| **S4 真实 dSPACE 上行** | 接真实反馈通道（电控侧配合） | 硬件交付 |
| **S5 现场标定与整定** | 真实手眼收敛验证、误差参数实测 | S4 |

## 6. 与现有模块的关系

- **不替换**：runTaskLoop（任务执行层）保留——顶层调用它执行任务
- **补充**：反馈读取、手眼估计、目标估计三个新模块
- **旧 TopLevelSystem.m**：结构参考（scheduler 骨架），实现替换为 S1 新顶层

## 7. 预期收益（量化目标）

- 目标定位精度：视觉原始误差 → 融合后 **提升 30-50%**（多帧 + 闭环）
- 手眼标定：**无需静态标定板**，任务过程自动收敛（2D 下 3 参数）
- 任务成功率：端到端提升（位姿更准 → 夹取/放置更稳）
