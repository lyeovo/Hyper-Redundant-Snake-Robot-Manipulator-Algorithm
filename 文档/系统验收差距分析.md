# 完整系统功能验收差距分析

> 依据用户提供的系统验收说明，分析当前软件部分的**缺失与未完成内容**。
> 机械臂：6 臂 × 1043.93mm；末端：夹爪（单电机开合）+ 视觉相机；视觉：YOLO 标签识别；电控：dSPACE。
> 任务链：**自主识别 → 驱动到物体附近 → 夹取 → 移动到目标位置 → 放下 → 结束**

---

## 1. 验收任务链分解

```mermaid
flowchart LR
    A[视觉感知<br/>YOLO 识别标签] --> B[位姿输出<br/>6DoF 六元矢量]
    B --> C[坐标系变换<br/>相机系→机械臂基座系]
    C --> D[任务生成<br/>夹取点/放置点 2D 投影]
    D --> E[运动规划<br/>IK/避障求解]
    E --> F[轨迹下发<br/>motorCmd → dSPACE]
    F --> G[电机执行<br/>关节+夹爪]
    G --> H[反馈闭环<br/>完成/失败/急停]
    H --> A
```

## 2. 已有 vs 缺失矩阵

| 环节 | 已有 | 缺失/未完成 | 优先级 |
|---|---|---|---|
| **视觉感知** | YOLO 靶标检测 + 白点精定位 + 6DoF 位姿估计（`yolo_marker_detector.py`、训练/评估脚本、模型 `marker_targets_best.pt`） | 真实相机联调（D405 + venv 环境，待现场） | P1 |
| **坐标系变换** | `projectTo2D`（相机系坐标直接当基座系，**仿真模式明确声明"标定前"**） | **手眼标定 `T_base_camera`**（外部依赖，未做——无真实机械臂/相机标定板现场） | **P0** |
| **任务生成** | `taskToSegments`（move_near_target/pick_target/pick_and_place/dock_to_interface/home）、夹爪状态机 gripper_seq、TaskCommand JSON 文件桥 | z 方向（相机高度→夹取高度）未建模——**验收为地面平面任务，z 固定可行，但夹爪行程/接近高度需与电控约定** | P1 |
| **运动规划** | 6 方法 + auto + graph + L2 策略；价值函数/障碍/收敛判定完整；测试 0 失败 | **真实电机参数缺失**（限位 ±3rad 默认、零位/正方向假设、速度上限未实测）；**末端几何（夹爪+相机偏置）未进运动学** | **P0** |
| **轨迹下发** | `exportMotorCmd`（q_seq/t_seq/gripper_seq/dq_max，.mat+.csv）、《电控对接说明》§2.1 格式 | 无 dSPACE 硬件——**下发只能仿真验证**；dSPACE 端加载器未写（属电控侧） | P1 |
| **电机执行** | —（dSPACE 侧实现，含夹爪状态机） | **执行完成/失败事件回传通道**（软件如何感知电控执行结果？当前为离线下发、无反馈） | **P0** |
| **反馈闭环** | `runTaskLoop` 任务状态机（RECEIVED→…→COMPLETED/FAILED/CANCELED/ESTOP）、急停隔离 | **电控执行反馈 → 软件状态机**未连通（当前状态流只覆盖"规划求解"阶段，不覆盖"电机执行"阶段）；夹取成功确认（夹爪到位/夹持力）未建模 | **P0** |
| **验收测试** | `test_all` 全量回归、`verifyPolicy` 策略级验证、任务桥 mock 端到端 | **系统级验收框架缺失**（视觉→任务→执行→回传的端到端指标：成功率/末端精度/节拍/碰撞） | P1 |
| **误差/鲁棒** | errorModel/assessRobustness/feedbackCorrect（σ_motor=0.01/backlash=0.005/κ=0.001） | 参数为**默认估计**，需真实电机实测校准；**视觉误差传播**（视觉位姿误差→任务精度）未建模 | P2 |
| **L2 策略** | CVAE 管线（示范生成→训练→部署闭环，90%/3.2s@旧臂长） | **臂长已纠正为 1043.93mm×6，需重训**（示范/模型均为 0.5m 口径；参数已就绪，待云服务器） | P1 |

## 3. 缺失项详表（按优先级）

### P0（阻塞验收，必须先完成）

| # | 缺失项 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| 1 | **手眼标定 T_base_camera** | `projectTo2D` 注释明确"标定前仿真模式" | 相机系位姿无法换算到机械臂基座系——**真实夹取无法定位** | 机械臂交付后现场标定（chessboard_calibration 已有标定代码基础）；标定前保持仿真模式 |
| 2 | **真实电机参数** | q_limits 默认 ±3rad、方向/零位假设 | 规划解可能超出真实电机行程/方向反 → 执行失败 | 从电控侧获取真实限位/零位/方向/速度上限，写入 modelDefaults |
| 3 | **末端几何（夹爪+相机）** | 运动学末端=最后关节 | 夹爪夹持点/相机光心与最后关节不重合——**夹取/视觉对位有固定偏差** | 确认末端偏置（rod_offset/夹爪长度/相机位姿）进运动学模型 |
| 4 | **电控执行反馈通道** | 当前离线下发（exportMotorCmd 后无回传） | 软件不知道执行是否成功/何时完成——**任务状态流断裂在"EXECUTING"** | 定义 dSPACE→软件事件（完成/失败/急停），扩展 runTaskLoop 状态机与 TaskStatus 字段 |

## 4. 结论

**软件核心（规划/任务/仿真/策略）完成度高**（约 90%），但**系统级集成尚有 4 个 P0 缺口**：
1. **手眼标定**（无真实机械臂无法推进——外部依赖）
2. **真实电机参数与末端几何**（需电控侧数据）
3. **电控执行反馈通道**（软件状态机与 dSPACE 执行结果的闭环）
4. 依赖 1-3 的**端到端真实联调**（P1#5）

**建议推进顺序**：机械臂交付前——完成 P1#8（云重训）与 P1#9（系统级验收框架，可先建 mock 版）；机械臂交付后——P0#1-4 现场标定与联调，P2 校准。
