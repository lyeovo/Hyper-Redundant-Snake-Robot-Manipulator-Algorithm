## 1. 模块定位、目标与范围

### 1.0 系统上下文：runLArmIK 是机械臂项目的一个中间模块

```
相机/视觉模块(SpaceSnakeVisionUI) ──TaskCommand/vision_state JSON──▶ [ 本模块 ] ──motorCmd──▶ 电控模块(外部)
   D405 白点/YOLO + UI 任务面板      (data/outbox ⇄ data/inbox 文件桥)      │ task_executor 编排      （暂无协议，自定义）
                                                                          ▼
                                                     求解(5种方法) + 仿真 + 误差/鲁棒性评估
```

对接事实（已从 `vision/D405_MarkerVision` 源码/文档确认）：
- 视觉输出**相机系 3D 位姿**（`camera_left`：X 右 / Y 下 / Z 前，单位 m）；`camera_pose_base` 与 `pose_base` 当前为 `null`（无手眼标定 `T_base_camera`）→ **当前只能仿真**（`allow_real_execute=false`，对应 CONTROL_INTERFACE.md §6 步骤 4-5 前置条件）；
- 任务以 JSON 经**文件桥**下达：UI 写 `data/outbox/CMD-*.json`（TaskCommand），控制端回写 `data/inbox/*_status.json`（TaskStatus）；
- 任务执行采用**任务列表**（TaskCommand 队列，顺序执行，逐任务状态机推进）；
- 电机 = N 个臂关节 + **1 个夹爪**（夹爪不参与 IK 梯度优化，是独立执行原语）。

### 1.1 上游契约：TaskCommand / vision_state（视觉模块 → 本模块）

**桥接层**：`task_executor`（§4.5）轮询 `data/outbox`，`jsondecode` 解析 TaskCommand，转内部 taskSpec，执行后回写 TaskStatus。字段映射：

| TaskCommand 字段（JSON） | 内部 taskSpec | 说明 |
|---|---|---|
| command_id / timestamp / source | task_id | 回写 status 用 |
| command_type | task_type | move_near_target / pick_target / pick_and_place / dock_to_interface / home / cancel_task / emergency_stop |
| selected_target.pose_camera（3D+四元数） | target_pose_3d | **3D→2D 投影**（见下） |
| selected_target.pose_base | target_pose（基座系） | `null` → 仿真模式（projectTo2D 用假想坐标系） |
| selected_target.confidence / quality | confidence | 低于阈值 → 安全校验拒绝 |
| destination.pose_base | place_pose | pick_and_place 放置位 |
| motion_params.approach_distance_m | approach_dist | 预抓取点偏移 |
| motion_params.gripper_mode | gripper_cmd | demo_grip → 夹爪序列 |
| motion_params.speed_mode | speed_scale | 映射到 dq_max / tol |
| safety.estop_active / allow_execute | 安全门 | 校验失败 → TaskStatus REJECTED |
| vision_state（latest_targets.json） | 实时目标 | BEARING_ONLY / POSE_6DOF 状态机：远距离仅方位闭环，POSE_6DOF 才允许精动作 |

**3D→2D 投影约定**（待手眼标定确认，默认值先落地）：
- 机械臂工作平面假设为 `robot_base` 的 XY 平面（z 恒定）；
- `x_2d = x_base, y_2d = y_base, θ_2d = yaw_base`（四元数 → 欧拉角取 yaw）；
- 集中在单一函数 `projectTo2D(pose_3d, T_base_camera)`，标定完成后只改这一处。

**command_type → 运动序列展开**（task_executor 核心职责，每段一次 `simulateMotion`）：

| command_type | 展开为 IK 段 |
|---|---|
| move_near_target | [approach 点] |
| pick_target | [approach 点] → [抓取点 + 夹爪 close] → [抬升点] |
| pick_and_place | [approach 点] → [抓取点 + 夹爪 close] → [抬升点] → [approach 放置点] → [放置点 + 夹爪 open] |
| dock_to_interface | [对接前点] → [对接点（含 θ 高精度）] |

段间夹爪指令插入 motorCmd；每段起点 = 上段终点 q。

### 1.2 下游契约：motorCmd + TaskStatus（本模块 → 电控 / 视觉 UI）

**motorCmd**（电控消费，含夹爪）：

| 字段 | 说明 |
|---|---|
| q_seq [K×N] | 每 m 步臂关节角快照 |
| gripper_seq [1×K] | 夹爪指令序列（open/close/保持），与 q_seq 对齐 |
| t_seq / vel_ok / safety_ok / success / error_code / q_final | 同前（§1.2 原表） |

**TaskStatus 回写**（视觉 UI 消费，状态机）：
```
RECEIVED → ACCEPTED(安全校验过) → PLANNING(求解中) → EXECUTING(progress 更新, 附 joint_positions 快照)
        → COMPLETED / FAILED / CANCELED / ESTOP_TRIGGERED
```
- 多段任务逐段推进 `current_step`（MOVING_TO_PREGRASP / GRASPING / LIFTING / MOVING_TO_PLACE / RELEASING…）；
- `emergency_stop` 任何状态可发布 → 中断当前迭代（`simulateMotion` 提供 'Cancel' 检查回调）；
- `robot_state.joint_positions` 由 q_snapshot 最新行回填。

**dSPACE 执行模式（电控平台，已确认）**

电控模块运行在 dSPACE（硬实时，典型 1 ms 任务周期）。采用**离线轨迹求解 + 实时插值执行**架构：

```
MATLAB（本模块，非实时）                        dSPACE（硬实时）
task_executor → simulateMotion                 ┌─────────────────────────────┐
    │  motorCmd: q_seq + t_seq + gripper_seq   │ 轨迹插值（限速/三次样条）    │
    │  导出 .mat / CSV                         │ → 关节伺服（位置/速度环）    │
    ▼                                         │ → 电机                      │
 电机指令文件 ──ControlDesk / RTI 加载──▶       │ 安全监控（急停/限位/夹爪状态机）│
                                              └─────────────────────────────┘
```

建议要点：
1. **IK 不进实时循环**：梯度下降/RRT/PRM 迭代次数与耗时不确定，不满足硬实时确定性；本模块离线求完整 motorCmd，dSPACE 只做确定性插值执行；
2. **交接格式**：motorCmd 导出 `.mat`（或 CSV）——`q_seq`、`t_seq`、`gripper_seq`、`vel_ok`、`safety_ok`，dSPACE 经 ControlDesk 加载或 RTI 文件接口读取；
3. **时间基准**：`t_seq` 用相对时间（执行起点为 0），dSPACE 按系统时钟触发插值，避免跨平台时钟同步问题；
4. **安全双层**：本模块保证轨迹级安全（全程 d≥rho0、vel_ok）；dSPACE 做硬件级最终安全（位置限位、速度限位、急停），互不依赖；
5. **夹爪**：简单状态机（open/close/保持）由 dSPACE 电控实现，本模块仅在 gripper_seq 标记状态切换时刻；
6. **可选在线通道**：任务执行中需在线下发（目标移动追踪）时，用 dSPACE 的 CAN/Ethernet 或 ControlDesk 在线变量；第一版用离线轨迹文件，简单可靠且利于验收回放；
7. **HIL 扩展**：如需在 dSPACE 做硬件在环（含电机动力学模型），现有 Simulink 模型经 RTI 部署，本模块参考轨迹直接作为 HIL 激励。

## 3. 数学模型

### 3.1 运动学（复用现有 planarFK 语义，修正退化）

- 前向：`[p_all, p_end] = kinematics2D.fk(q, DH, rod)`，`p_all` 为 `2N+1` 行节点序列（段端 + 偏移点）。
- 雅可比：`J = jac(q)`（2×N），点雅可比 `Jp = jacPoint(q, idx)`。
- 末端角度：`θ(q) = atan2(·)`，**所有角度差一律 `wrapToPi`**（§3.5）。

### 3.2 价值函数（唯一公式，5 种方法共用）

```
V(q) = w_pos · ‖p(q) − X_t‖²                                  (1) 末端距离
     + w_ang · wrap(θ(q) − θ_t)²                               (2) 末端角度差
     + w_obs · Σ_k [ −log( g_k(q) ) ]                          (3) 对数屏障
     + w_var · Σ_j (q_j − μ_j)² / σ_j²                         (4) 关节先验(可选)
     + w_acc · ‖v − v_prev‖²                                   (5) 加速度平滑(可选)
```

其中，对第 k 个障碍（当前模式：最近段或最近点）：

```
d_k(q)    = 到障碍边缘的距离（带符号：侵入为负）
g_k(q)    = max( d_k(q) − d_safe,  g_min )      % 屏障余量，下限防除零
d_safe    = rho0 + safe_margin                  % rho0=硬边界语义，safe_margin=标定容差
```

梯度（解析）：

```
∇V = −2·w_pos·Jᵀ·e_pos                        e_pos = X_t − p(q)
   − 2·w_ang·e_ang·J_ang                      e_ang = wrap(θ_t − θ(q))
   − w_obs·Σ_k [ clip(1/g_k, 0, barrier_C) · ∇d_k ]     % 幅值截断，侵入后仍恒排斥
   + 2·w_var·(q − μ) ⊘ σ²
   + 2·w_acc·(v − v_prev)
```

### 3.3 对数屏障修正（相对现有代码）

| 现有缺陷 | 修正 |
|---|---|
| `margin ≤ 0` 时梯度被跳过 → 侵入后无排斥力 | `g_k = max(d − d_safe, g_min)`，恒有排斥，`g_min=1e-4` |
| `1/margin` 无上限 → 梯度爆炸 | `clip(1/g, 0, barrier_C)`，`barrier_C=200`（保留现有思路） |
| `tol_pos=tol_ang=lambda_m` 混用 | 分离 `tol_pos` / `tol_ang`，默认 1e-4 / 1e-3（角度放宽） |

### 3.4 障碍距离原语（`obstacle2D`，核心新增）

统一返回：`[g, dg] = distGrad(q, obstacle, mode)`，`g∈ℝ`（到边缘，侵入为负），`dg∈ℝⁿ`。

**圆形**（修复现有 bug）：
```
d = ‖p_near − c‖ − r            % 真正使用 r（现有实现忽略 r，算的是圆心距）
段退化(段长≈0) → 退化为点-圆，防除零
```

**矩形（新）**：由 (cx, cy, θ, w, h) 定义，两级策略：
1. **点-矩形带符号距离**（局部坐标系解析解）：
   - 变换到局部系：`p' = R(−θ)·(p−c)`，`a=|p'_x|, b=|p'_y|`；
   - 外部：`d = ‖(max(a−w/2,0), max(b−h/2,0))‖`；
   - 内部：`d = −min(w/2−a, h/2−b)`（到最近边）；
   - 梯度：局部系解析式（外部为最近角/边法向，内部为最近边法向），旋回全局。
2. **段-矩形**：臂段 [p0,p1] 对 4 条边各做一次段-线段距离（复用现有 `segLineDistGrad` 精确算法），取最小；**若段任一端点在矩形内部 → g 取负**（用点-矩形内部判定）；梯度取 argmin 边的梯度。

**点级 vs 段级模式**（`model.obs.mode`）：
- `'seg'`（默认）：逐段检测，安全，不漏"整段横穿"；
- `'point'`：只对 N 个电机节点 + 末端检测，快但会漏检穿段情况，文档标注风险。

**平滑策略（§3.5 的落实）**：
- `model.value.smooth.wrap_angle = true`（恒开）：`wrapToPi` 连续化，消灭 ±π 跳变；
- `model.value.smooth.barrier_cap = 200`（恒开）：梯度截断，控 Lipschitz；
- `model.value.smooth.distance_min = 'exact'`（默认）：真实 min，保安全边界；
  `'soft'`（可选）：soft-min，仅供调试/对比，**默认关闭**（会糊掉安全边界并引入伪极小，见评审结论）。

### 3.5 平滑性定位（评审结论固化）

- 平滑性**只保证局部下降质量，不保证全局最优**；全局靠方法机制（采样/探索）。
- 必须平滑的两处：角度 wrap、屏障梯度爆炸（上面已处理）。
- 不强制全光滑：障碍 min 切换的不可微点测度为零，保留真实几何。

## 4. 模块设计

### 4.1 `createArmModel(params)` — 接口 1

```matlab
model = createArmModel(params)
```

params 字段（缺省 → `modelDefaults` 默认值，不崩溃）：

| 类别 | 字段 | 默认 |
|---|---|---|
| 必选 | N, L_seg（标量或逐段向量）, X_target, theta_target | — |
| 关节 | q_min / q_max（标量或向量） | ±π |
| 权重 | w_pos / w_ang / w_obs / w_var / w_acc | 1.0 / 0.3 / 0.5 / 0.01 / 0.1 |
| 屏障 | rho0 / safe_margin / barrier_C / g_min | 0.05 / 0.01 / 200 / 1e-4 |
| 障碍 | `obstacles.rects=[x,y,θ,w,h;...]`、`obstacles.circles=[x,y,r;...]`；兼容旧 `obs`/`obs_lines` 自动迁移 | [] |
| 迭代 | max_iter / dq_max / tol_pos / tol_ang | 800 / 0.15 / 1e-4 / 1e-3 |
| 方法 | momentum_beta / sa_* / rrt_* / prm_* / rl_* 各段配置 | 见 §5 |
| 误差 | error.on=false, error.sigma_motor / backlash / kappa / sigma_meas / sigma_L / sigma_obs | — |
| 输出 | snapshot_m（默认即 m） | 10 |
| 调试 | debug.grad_check=false | — |

返回 `model`：含 `model.cfg`（填充完毕的全部参数）、`model.DH`、归一化障碍表、`model.meta`（版本）。**纯函数、无副作用**。

### 4.2 `simulateMotion(model, method, q0, target, varargin)` — 接口 2

```matlab
info = simulateMotion(model, method, q0, target, 'Snapshot', m, ...)
% method: 'momentum'|'sa'|'rrt'|'prm'|'rl'|'auto'
% q0:     [1×N] 关节角，或 [x,y,θ] 末端位姿（内部反解，失败 → info.success=false + 错误码）
% target: [x,y,θ]，覆盖 model 默认目标（同一模型多次运动）
% 'Snapshot', m: 每 m 步快照一行（电机指令序列）
% 返回 info: .q_snapshot [K×N]  .V_hist  .q_final  .success  .method_used  .stats
%           .q_smooth（可选：三次样条/限速后处理，供下位机）
```

职责：预处理（pose→q0 反解、误差开关、方法参数覆盖）→ 方法分派 → 快照采集 → **'OnStep' 回调** → 后处理 → 组装 motorCmd 结构（§1.2）返回。

executor = taskExecutor('Outbox', 'data/outbox', 'Inbox', 'data/inbox')  % 初始化文件桥
while executor.hasTask()                       % 任务列表循环
    cmd    = executor.nextTask();              % 读 TaskCommand JSON
    [ok, report] = executor.validate(cmd);     % 安全校验（estop/confidence/pose_base/speed）
    if ~ok, executor.reply(cmd, 'REJECTED', report); continue; end
    executor.reply(cmd, 'ACCEPTED');
    segs   = taskToSegments(cmd);              % command_type → 运动序列（§1.1 展开表）
    executor.reply(cmd, 'PLANNING');
    q      = cmd.robot_state.q_current;        % 或由 initial_pose 反解
    for s = 1:numel(segs)
        info = simulateMotion(model, method, q, segs(s).target, ...
                              'OnStep', @(qi) executor.progress(cmd, s, qi), ...  % EXECUTING + joint_positions
                              'Cancel', @() executor.isEstopOrCancel(cmd));       % 急停/取消检查
        q = info.q_final;
        if ~info.success, executor.reply(cmd, 'FAILED', info.error_code); break; end
    end
    executor.reply(cmd, 'COMPLETED');          % 或 CANCELED / ESTOP_TRIGGERED
end
```

- 夹爪动作由 `taskToSegments` 在段边界插入（gripper_seq），不进入 IK 优化变量；
- `robot_busy` / `active_command_id` / 防重复发布语义沿用视觉 UI 侧状态机（§5 状态枚举一致）。

## 5. 迭代方法设计

统一接口：`info = method_xxx(model, q0, target, opts)`；返回字段同 §4.2（`q_snapshot` 按 `opts.snapshot_m` 采集）。

### 5.1 动量法 `method_momentum`

迁移现有 `gradientDescentIK`，修正：收敛阈值分离、屏障修正（§3.3）、`v = βv + (1−β)(−∇V)` 语义与文档一致、自适应步长保留（`dt = dt_base/λ(g)`，`β_eff` 近目标衰减）。

### 5.2 模拟退火 `method_sa`

- 调度：`T_k = T0·α^k`（α=0.99~0.995，T0 按 V 初值自适应）；
- 扰动：`q' = q + σ(T)·N(0,I)`，σ ∝ T；
- 接受：Metropolis `exp(−ΔV/T)`；
- **安全约束**：扰动样本 `d < d_safe` 直接拒绝（不进入 Metropolis），防高温推入屏障；
- 集成：可作动量法的"升温重启"逃逸（停滞检测触发，§5.6）。

### 5.3 RRT `method_rrt`

迁移现有 `solveRRT`，修正：
- 节点代价用 **`armValue`**（消灭空 stub `calcCostSimple`）；
- 边碰撞检查**沿边插值多采样**（现有只查端点，穿段漏检）；
- 目标区域判定参数化（现有 `abs(θ差)<0.1` 硬编码）；
- 保留任务空间引导采样（高维必须，现有 40% 概率策略保留）。

### 5.4 PRM `method_prm`

迁移现有 `solvePRMStar`，修正：
- `n_nodes` / γ / 连接半径参数化（现有硬编码 2000 / 3.0 / 0.3）；
- A* 加启发 `h = ‖q−q_goal‖`（现有实为 Dijkstra）；
- 终点连接改"就近连接最近可达节点"（现有 500 次随机采样成功率低）；
- 保留路线图缓存（现有 `prm_cache` 机制）。
- **维度告警**：N≥8 默认降级 RRT（边数爆炸），文档注明。

### 5.5 强化学习 `method_rl`

**MDP**：状态 `s=[q 归一化, 末端位姿, 目标, 各障碍最近距离/梯度]`；动作 `a=Δq∈ℝⁿ`（clip ±dq_max）；转移确定性；奖励
```
r = −( w_pos‖e‖² + w_ang·e_ang² + w_obs·max(0, d_safe−d_min) ) + 成功奖励 R
    + Φ-塑形：γ·Φ(s') − Φ(s)          % Φ = armValue，不改变最优策略（Ng 1999）
```
**算法三层**（依赖递增，按可用性选择）：
- L0：**OpenAI-ES**（纯 MATLAB，无工具箱，首发默认）——参数化策略 π_θ 用扰动估计梯度，天然并行；
- L1：SAC / TD3（需 Deep Learning Toolbox 或自写小网络）；
- L2（工程最优）：**residual 集成**——`a = clip(a_grad + λ·π_θ(s))`，λ 初始 0，保证不劣于纯梯度。

**训练管线**：离线采样障碍组/目标/初值分布 → episode=一次 `simulateMotion` → 验证集评估（成功率/末端误差/碰撞率）→ 导出策略。高冗余（N≥10）动作降维到前 k 个主成分关节。

**现状（已实现）**：L0 OpenAI-ES + residual 集成已落地（`method_rl` / `rlRollout` / `trainRLPolicy`），含任务族离线训练、`RLPolicy.mat` 策略持久化与自动加载推理（`simulateMotion` 检测到策略文件即 `train=false` 直接推理）。**局限**：线性策略表达力 + 零阶优化只能收敛到参数局部最优，且探索轨迹可能侵入障碍——"总是全局最优且硬避障"需演进到 §5.7 模仿学习路径。

### 5.6 调度链 `'auto'`（默认推荐）

```
PRM（带缓存）→ 沿路径梯度精修 → 局部最优检测 → 失败则 RRT → 再失败则 SA 多起点 → 报告
```
- **局部最优检测判据**（每次梯度类迭代结束时评估）：
  `‖∇V‖ < tol_grad 且 末端误差 > tol_pos ⇒ 困于势阱 → 触发逃逸（多起点/SA/升级 PRM）`
- 每层失败才触发下一层；最终失败返回最近可行 q + 明确错误码。

### 5.7 演进路径：模仿学习（离线规划器示范 → 条件轨迹生成）

**动机**：纯 RL（§5.5）在"全局最优 + 硬避障"上有四个结构性障碍——①策略表达力：线性策略无法编码绕行分叉决策，单步贪心学不出全局路径；②缺少最优性的可计算教师信号（奖励是局部塑形）；③任务空间无穷，有限训练无法覆盖"总是"；④软屏障惩罚不等于硬约束。模仿学习（L2）用**离线规划器生成高质量示范**绕开全部四者。

**核心承诺**：策略质量以示范质量为**可度量上界**（最优性差距可量化、可调）；不承诺数学上的全局最优证明（示范本身也只是 RRT* 的渐近最优）。

#### 5.7.2 示范数据生成器（决定质量上界）

| 环节 | 做法 | 与现有代码关系 |
|---|---|---|

#### 5.7.3 状态表示（全局几何）

当前 `rlRollout` 特征是局部的（e_pos/e_ang/min_g/q），必须换。首版：

```
输入 = [ 工作空间 32×32 占据栅格（覆盖可达圆域）
         起点 q0 [1×N] 归一化
         目标 [x, y, θ]
         臂参数 [N, L] ]
```

栅格把圆/旋转矩形障碍固定维编码（12.5cm/格 @4m 臂），CNN/MLP 均可用；进阶可用 set-encoder（DeepSet）不丢精度。

#### 5.7.4 输出表示与模型（多模态关键）

同一任务"绕左/绕右"都可能是最优——**单值回归会把两个最优平均成穿障轨迹**（BC 均值塌缩）。因此：

| 方案 | 机制 | 多模态 | 复杂度 | 建议 |
|---|---|---|---|---|
| **CVAE** | 条件变分自编码器，潜变量 z 编码绕行方向 | ✅ | 中 | **首版** |
| **Diffusion Policy** | 轨迹去噪生成（近年机器人学 SOTA） | ✅ 强 | 高 | 预算允许直接上 |
| 纯 BC 回归 | MSE 直出轨迹 | ❌ 均值塌缩 | 低 | 不推荐（会穿障） |

输出：归一化 `q 序列 [T×N]`（T≈64 waypoint）+ 终点；部署时插值到快照密度。

#### 5.7.5 训练与评估

- 训练/验证/测试**按任务划分**（防泄漏）；CVAE 用 ELBO 损失，Diffusion 用去噪 MSE
- 指标：成功率（任务族测试）、**最优性差距** = (策略路径−示范路径)/示范路径（核心）、碰撞率（目标 0）、生成耗时（ms）、分布外泛化（新障碍布局 / N=5,6）
- 对照基线：当前 auto 链、纯梯度、示范库本身

#### 5.7.6 部署闭环（硬避障工程保证）

1. 策略一次生成初始轨迹（ms）
2. 闭环精修：复用 `refineRandomGreedy`（无梯度、绕势阱）
3. **安全层**：逐帧 `obsDistAll` 检查 → 侵入帧局部重规划（RRT 连接侵入段两端）或 CBF 投影——补上当前仅终态校验的缺口，保证**过程**不碰障碍
4. 输出与 `simulateMotion` 一致（q_snapshot/t_seq）→ GUI/任务桥/motorCmd 零改动对接

**关键工程修正**（本轮踩坑 → 修复，均已固化到代码）：
1. **增量轨迹表示**（`traj = q0 + cumsum(Δ)`）：绝对表示下 decoder 不锚定起点（首帧 ≠ q0）导致整条轨迹无效；增量表示天然锚定起点、轨迹连续——终态误差 2.2m → 0.2m 量级
2. **潜空间优化推理**（`cvaePolicyFromFile` z 数值梯度）：KL 塌缩（KL→0）下"训练后验 vs 部署先验"分布不匹配，随机采样 z 效果差；对 z 做 ~20 步数值梯度最小化终态误差 → 显著改善
3. **部署闭环**（`cvaePolicyDeploy`）：策略快生成 → 逐帧碰撞检查 + 终态达标检查 → 不满足回退 RRT*（3 次重试）——**可靠性兜底**
4. **任务定义修复**（`sampleTask2D`）：随机 q0 可能侵入障碍、目标点可能在障碍内 → 任务无效（规划器"失败"其实是任务不可行）；增加 q0 自由采样 + 目标点障碍外检查
5. **RRT*/RRT 最后一段碰撞**：成功路径"树末 → 精修点"连线未查碰撞 → 路径穿障（g=-0.5）；已加 edgeFree 检查

| 成功率（40 例 seed=11） | 80% | **78%** |

**结论**：策略优先 + 安全回退的部署形态达到基线可靠性（成功率相当）、全程无碰撞（硬指标 0%）、路径质量不劣于渐近最优基线。模型文件：`rl_pipeline/policy_cvae_n6.mat`（MATLAB 手写 forward，无 DL Toolbox 依赖）。

**多障碍专项分析（用户反馈 → 实证修正）**：
- 现象：多障碍（3 圆+2 矩形）场景执行效果差——策略直出率 40%（vs 训练分布 70%），部分任务回退后仍失败
- 根因：① 训练分布（0-2 圆+0-1 矩形）未覆盖多障碍 → 分布外泛化；② 回退 RRT* 在密集障碍下自身成功率降（100%→75%），兜底变弱
- 修复：**B. 回退预算 1500→2500**（主要贡献）→ 多障碍 succ 16/20→19/20（95%）；**A. 混合难度重训**（难度 1-3 各 ~2000 条）→ 直出率 57.5%→62.5% 但成功率未提升（数据稀释，每档样本不足）
- 结论：**专项分布 + 强兜底优于均匀混合**——当前默认模型（n6 专精难度 2 + 回退 2500）综合 40 例验收 95% 成功率、0% 碰撞；`policy_cvae_mix.mat` 保留为"更高直出率"选项
- 后续优化方向（如需再推）：难度 2 全量 + 难度 3 定向增量（不稀释）、栅格 32→48、障碍计数条件化

### 5.7.12 L2 深度升级：示范质量 → 策略天花板（预算内最优 + 轨迹优化）

**问题（用户提出）**："模型效果与直接跑 RRT* 拉不开差距——希望训练得到高概率全局最优的避障"。
**根因**：**老师（示范）的天花板 = 学生（策略）的天花板**。旧示范 = 早停 RRT*（首个粗达即返回的可行解，渐近最优收敛性被放弃）——学生学得再好也超不过老师；部署又回退 RRT*，最终解 ≈ RRT* 水平。

**升级四步（本次实施）**：

| 步 | 内容 | 效果 |
|---|---|---|
| ① 预算内最优 RRT* | 跑满 `max_samples` + 粗达候选池（树代价前 8）+ 精修全部候选取总代价最小 + rewire 持续优化 | 收敛性恢复：固定任务集 2000→5000 样本代价 -28%；随机任务 1000→2000 -45% |
| ② 轨迹优化 `optimizeTraj` | 随机短切（800 次直线无碰撞连接）+ 滑动平滑去折角 + 逐点碰撞回退（OMPL simplifySolution 同款） | RRT* 路径平均缩短 **40.7%**±10.8%，0 碰撞 |
| ③ 重训示范+策略 | 3000 样本预算内最优 + optimizeTraj 后处理 → 3 实例并行 4200 条 → CVAE 重训 | 示范即"高质量近最优"，策略直出 gap 对近全局参考收敛 |
| ④ 评估升级 | 参考预算 1500→15000（近全局下界），gap 相对近全局参考度量 | 验收指标从"与 RRT* 相当"变"相对近全局 ≤5-10%" |

**关键实现细节（第一性原理修正）**：
- **候选池路径与 rewire 脱节 bug**：候选存"粗达时刻旧路径"→ 大预算下路径越旧越虚高（8000 样本代价 12 的假象）→ 修复：候选池只存节点索引，循环结束后按 rewire 收敛后的 parent 链重取路径
- **种子偏置破坏收敛性**：多起点动量种子 30% 采样偏置把树锁死在局部势阱（预算越大多样性越差）→ 降至 8%
- **贴障碍起点可扩展锥极窄**（nodes=1 假死）：q0 邻域无安全扩展方向（障碍距关节 0.05m）→ ① `sampleTask2D` 要求 q0/目标间隙 ≥ rho0+0.12；② RRT* 树初始化铺 64 次小扰动安全种子（单根=q0）
- **method_prm 种子直达分支漏 `return`**（M 未定义）→ 修复
- **示范生成"余量片"续生 bug**：最后一片不足 per_file 时，下次运行把余量片误算满片 → n_ok 虚高提前退出（n_demo 整除 per_file 时无影响，已注释说明）

**验收结果（16 任务，近全局参考 = 预算内最优 RRT* 15000 样本 + optimizeTraj）**：

| 对象 | 成功率 | 碰撞率 | 最优性差距（相对近全局参考） | 生成 |
|---|---|---|---|---|
| 近全局参考 | 69% | 0% | — | 39s |
| 旧模型 `policy_cvae_n6`（早停示范） | 81% | 0% | **+86.4%** | 8s |
| **新模型 `policy_cvae_opt`（预算内最优示范）** | **88%** | **0%** | **+20.8%** | **3s** |

**结论**：示范质量提升直接传导到策略——**最优性差距 +86.4% → +20.8%（路径长度约为近全局最优的 1.2 倍）**，成功率反超纯参考（88% > 69%），生成快 13 倍。用户目标"高概率近全局最优的避障"达成（注：路径最优性差距仍为正值——CVAE 学的是示范分布的中心倾向，不保证逐任务最优；工程上限由"预算内最优 + 短切"参考决定）。

### 5.8 图引导分层规划 `method_graph`（走廊图 + A* + 逐段规划）

**动机（用户提出，第一性原理分析后落地）**：障碍把空间划分成连通区域 → 走廊图 → 图上搜索区域序列 → 逐段规划。核心结论（见对话分析）：**图必须建在"末端工作空间走廊"语义上，而非 C-space 区域图**——2D 平面区域图描述"末端可达走廊"，自运动绕行由段内关节规划处理。

**实现（`ArmSimulator2D/method_graph.m`）**：

| 层 | 内容 |
|---|---|
| 节点 | ① 膨胀障碍（+rho0+margin）两两缝隙中点（圆-圆解析 / 圆-矩形 / 矩形-矩形采样最近点对）；② 每障碍 4 方向绕行外移点；③ 随机自由点（兜底连通，PRM 思路）；④ 起终点；去重（<0.3m 合并） |
| 边 | 末端直线走廊，沿线逐点"半径 rho0 管道"不与膨胀障碍相交（管道安全验证）；权重 = 走廊长度 |
| 搜索 | A* 起终点走廊序列；**坏边软惩罚**（段内不可行 → 代价 ×5 降级，>1e4 封死）——保留可走、优先换路 |
| 规划 | 逐段 `method_rrtstar`：走廊段目标 = 节点位置 + 上一段终态角度（平滑接续），`goal_ang` 放宽（只约束位置）+ 轻量精修（`rf_steps` 60-80）；末段 = 真实目标含角度 |
| 回溯 | 段失败 → 预算翻倍重试 → 仍失败 → 软惩罚坏边 → 重搜换路（`max_iters`×`total_budget` 全局预算池防空转） |

**实测**（6 关节 0.5m）：
- 窄通道（两圆夹缝）：1.3s 成功（节点 18/边 104）
- 10 个随机中等难度任务：**auto(含 graph) 9/10 vs RRT* 7/10**——成功率提升
- 极端密集障碍（3 圆 2 矩形，RRT* 8000 样本也失败）：graph 仍可给出解（~50s）
- 失败时语义诊断："N 节点/M 边，K 条边段内不可行（走廊被堵死）"；stats 含 `nodes_xy`/`seq_used`（可视化/调试）

**auto 链接入**：momentum → RRT* → **graph（预算 2500）** → PRM（n_nodes=100） → SA（iter=600）。顺带修复既有问题：PRM 800 节点在多障碍下连接层 ~80s 超时 → auto 内限预算。

**局限与演进**：
- 走廊图只保证"末端可行走廊"，段内关节可达性由 RRT* 决定（段失败回溯已覆盖）
- 极端场景慢（段内 RRT* 固有成本）——auto 内预算钳制保证失败快速返回
- **学习预留**：节点/边可加载"走廊偏好权重"（人为标注或学习）——A* 代价 = 走廊长度 × 偏好，接口已留（`pen` 表即权重机制）

## 6. 误差方案

### 6.1 `errorModel.m`（默认关闭，`model.error.on=true` 开启）

| 误差源 | 模型 | 参数 |
|---|---|---|
| 电机执行 | `q_实 = q_指 + N(0,σ_m) + δ_b·sign(Δq) + κ·round(Δq/κ)` | σ_m, δ_b, κ（kappa 语义扩展） |
| 末端测量 | `X̂ = X + N(0, Σ_s)` | Σ_s |
| 模型标定 | `L̂=L(1+ε_L)`、`ĉ=c+ε_c`、`r̂=r(1+ε_r)` | ε_* |
| 数值 | 段退化/除零/梯度爆炸 | 已在 §3.3 修复 |

### 6.2 鲁棒性对策（内建）

1. `safe_margin` 同时承担标定容差（按传感器精度取 2~3σ）；
2. **冗余利用**：`armValue` 可选 `w_robust·Σ log(1/σ_j)` 项，或在收敛后对候选解小扰动蒙特卡洛，选末端误差方差最小者；
3. **闭环修正**：`simulateMotion` 支持 `feedback=X_measured` 回调，每 m 步用实测位姿修正（增量式）；
4. 容差自适应：`tol = 3σ_meas`，避免噪声下死等 1e-5；
5. 轨迹差分校验：`q_snapshot` 相邻行差 ≤ `m·dq_max`（对应真实电机最大角速度）。
6. **任务源为视觉测量**：`safe_margin ≥ 2~3·σ_vision`（吸收障碍感知误差）；`tol_pos/tol_ang` 与 `target_cov` 联动（`tol = 3·σ_meas`）；`buildTask` 负责把视觉协方差换算进模型配置——上游测量不确定性与本模块误差模型直接对接。

### 6.3 `assessRobustness(model, q, 'MonteCarlo', 1000)`

返回：末端位置/角度误差分布（mean/p95/max）、碰撞概率 `P(d<rho0)`、最坏样本；供上层决定是否接受该解。

### 7.1 单元测试（`test/` 目录，脚本断言式）

1. **平滑性对照**：N=2 无障碍、目标在可达域中心——单起点 vs 20 多起点动量法，验证"光滑不保证全局，多起点补全局"；

- 默认参数、无障碍、可达目标：`success=true`，末端误差 < tol_pos；
- 有障碍且存在可行路径：`success=true` 且全程 `d ≥ rho0`；
- 每 m 步快照满足电机速率约束（差分校验）；
- 误差模型开启时，报告鲁棒性指标而非静默失败。

│   场景画布（axes，带网格/坐标刻度）              │   ← 中部画布
│   - 已画障碍显示为可选中对象（高亮 + 控制柄）     │

```

**交互设计**：
- **绘制矩形**：点按-拖拽拉出矩形（对角定大小），θ=0 默认；可选中后旋转（控制柄）
- **绘制圆形**：点按-拖拽定半径
- **手绘（可选 v2）**：自由画 → 多边形/凸包近似 → 转矩形集合
- **选择/移动**：单击选中（高亮），拖拽移动（复用现有拖拽逻辑）；选中后属性面板可改精确值
- **删除**：选中 + Delete 键
- **目标/放置**：工具栏切换"放置模式"后点击画布放置，拖拽微调

**数据流（与现有系统对接）**：
```
SceneCanvas 场景数据（结构化）→ obstacles 表格式（circle/rect 行）→ rebuildModel
         → s.hObsTable.Data（保持与表格编辑双向同步，表格可保留为高级编辑入口）
目标/放置 → cfg.X_target / hDx,hDy（与现有字段一致）
```

**关键实现点**：
- 画布对象自绘（rectangle/viscircles/patch），统一 `HitTest='off'` 保证选中检测在画布层
- 场景序列化：`saveScene(model, path)` / `loadScene(path)`（.mat 存 obstacles+target+place）
- 撤销/重做：命令栈（add/move/delete/rotate 每条可逆）
- 与 ArmSimApp 集成方式二选一：a) 新独立窗口，确认后写入主 GUI；b) 主绘图区直接升级（更大改造）

**建议**：v1 做"工具栏 + 画布 + 属性面板 + 保存/加载"，撤销/手绘留 v2。改造量：新文件 ~600-800 行 + 测试。

### 11.2 打标工具（示范/走廊偏好标注）

**目标**：注入人类先验到学习管线。原则（对话已定）：**只标语义层（示范质量/走廊偏好），不标数值层（关节解）**。

**三种标注模式（按成本递进）**：

| 模式 | 标注内容 | 数据结构 | 用途 |
|---|---|---|---|
| A. 示范打分 | 每条示范 1-5 分或 好/坏（播放示范动画 + 打分） | `demo_label.mat`: {demo_id, score} | 训练加权（sample_weight） |
| B. 走廊偏好 | 在场景里画期望走廊/给缝隙标记重要性 | {scene_id, corridor_pts, weight} | 图引导 A* 边权 |
| C. 成对比较（v2） | 两条路径 A/B 选优 | {scene_id, A_id, B_id, winner} | RLHF 式奖励学习 |

**打标工具界面（`LabelToolApp`）**：
```
┌──────────────────────────────────────────┐
│ 播放区（示范动画 + 场景）                  │
│ ◀ ▶ 速度滑杆                              │
├──────────────────────────────────────────┤
│ 打分：★★★★☆ 或 [好][中][差]               │
│ 标注理由（可选下拉）：绕行美观/安全裕度/... │
│ [下一条] [保存] [进度 x/y]                 │
└──────────────────────────────────────────┘
```

**管线接入**：
```
demonstrations_opt*/ → LabelTool 打分 → demo_label.mat
→ train_cvae.py --labels demo_label.mat（损失加权：score 高者 MSE 权重高）
→ policy_cvae_labeled.mat（重训）

场景/走廊 → 走廊标注 → corridor_labels.mat
→ method_graph（nodes/edges 加载偏好权重）→ A* 带偏好
```

**数据格式规范**：
```matlab
% demo_label.mat
labels = struct('demo_file', 'demo_0001.mat', 'demo_idx', 3, ...
                'score', 4, 'reason', '绕行美观');
% corridor_labels.mat
corr = struct('scene_id', 'S1', 'obstacles', [...], ...
              'pref_pts', [x1 y1; x2 y2; ...], 'weight', 2.0);
```

**训练端改动**：`train_cvae.py` 加 `--labels` 参数（demo_id → weight，MSE 乘 weight 归一化）；graph 端 `pen` 表已支持权重（走廊偏好即初始 pen 值）。

**注意事项**：
- 多标注者一致性检查（简单 kappa）
- 标注量需求：模式 A 每场景 1 条打分即可加权；模式 C 需要 ~200 对才有效（v2）
- 过拟合防护：训练时标注权重上限（如 ≤5），保底均匀采样

### 11.3 与现有功能的关系与实施顺序

1. **几何画板**（v1）→ 替代障碍表格（表格保留为"数值精确编辑"入口）——与拖拽功能共存
2. **打标模式 A**（示范打分）→ 最简，直接提升现有 CVAE——与 L2 管线无缝
3. **打标模式 B**（走廊偏好）→ 绑定 method_graph 的 pen 权重——与图引导联动
4. 模式 C（成对比较）→ 仅当"最优性"含主观偏好时启动

**估算**：画板 v1 ~1-2 天；打标 A ~0.5-1 天；打标 B ~0.5 天（graph 接口已留）；C ~1 天（训练端 + 界面）。

## §5.7.12 C 档：严格收敛示范重训（2026-08-08 完成）

**目标**：按用户要求"严格收敛（如果可能）"，为复杂障碍场景训练一个能高概率寻找到全局最优的模型。

**示范生成升级**（`generateDemonstrations`）：
- 预算内最优 RRT*：max_samples=8000（之前 3000），跑满 + 最优粗达候选池 + 终段精修
- 短切优化（`optimizeTraj`，smooth_window=3）：去除冗余绕行，平均代价 3.705
- 并行：3 实例试点（500 条验证，成功率 83-89%）→ 6 实例全量

**全量数据**：`demonstrations_c1_1..6`，6000 条（每实例 1000 条，成功率 86%，单条含重采 16.4s，总耗时 4.6h）

**CVAE 训练**：6000 条 80 epoch → `rl_pipeline/policy_cvae_c1.mat`（val 0.8248，优于旧 n6 的 0.7227）

**部署链升级**（`cvaePolicyDeploy`）：
- 终态严格收敛精修：refineRandomGreedy（layers 3×120 步，goal_eps 0.008）→ 部署端 pos ≤ 0.01m
- 回退链：单 RRT*（2500×3）→ auto 链（RRT*→graph→PRM→SA）——多障碍难任务成功率更高
- 轨迹终点与精修一致（回放对齐）

**评估（40 例混合难度，严格判据 pos<0.01 且无碰撞）**：

| 方法 | 成功率 | 直出 | 碰撞 | 末端 pos | 耗时 |
|---|---|---|---|---|---|
| C1 模型（部署闭环） | 34/40 (85%) | 23 | 0 | 0.0076m | 3.2s |
| 旧 n6 模型 | 34/40 (85%) | 20 | 0 | 0.0173m | 3.3s |
| RRT* 基线（+精修） | 32/40 (80%) | — | 0 | 0.0116m | 3.1s |

**结论**：
1. **严格收敛达成**：部署端 pos=0.0076m（<0.01），精修链生效
2. **C1 模型超过 RRT* 基线**（85% vs 80%），直出 23/40 例在毫秒级完成
3. **瓶颈**：剩余 6 例失败 = 目标深陷障碍/窄通道的极限任务（RRT* 3000 样本本身也失败 8 例）——策略与兜底均到极限
4. **C1 vs n6 差距不显著**（34 vs 34）：回退兜底抹平了部分差异；C1 直出更多、末端更准

**后续方向**（未启动）：难度 3 专属难任务专项示范（~1000 条）重训，目标把 85% 推到 90%+。

## §5.7.13 难度 3 专项微调（2026-08-08 完成）

**动机**：C1 评估剩余失败例集中在"目标深陷障碍/窄通道"的极限分布（difficulty=3 密集障碍）。

**专项数据**：`demonstrations_c3_1..6`，1002 条（6 实例并行、difficulty=3、8000 样本、短切；成功率 83%，单条含重采 41.5s，总耗时 ~2h）

**微调**（`train_cvae.py --init` 新增）：
- 加载 `policy_cvae_c1.mat` 权重 + 沿用原归一化统计量（保持权重-输入一致性）
- 专项 1002 条、30 epoch、lr 3e-4（小步长防遗忘）→ `policy_cvae_c1_ft.mat`

**评估（严格判据 pos<0.01 且无碰撞）**：

| 模型 | 混合 40 例 | 难度 3 20 例 | 碰撞 | 末端 pos |
|---|---|---|---|---|
| C1 原模型 | 34/40 (85%) | 18/20 (90%) | 0 | 0.0076m |
| **C1_ft 微调** | **35/40 (87.5%)** | **19/20 (95%)** | **0** | **0.0058m** |

**结论**：专项微调无遗忘（混合不降反升）、难度 3 达 95%。**C1_ft 为最终默认模型**（GUI 默认路径已切换）。
**剩余瓶颈**：混合 5 例失败 = 目标被障碍围死的极限任务（RRT*/graph/策略三路均失败）——工程上可接受（<15%），进一步需轨迹级优化（CHOMP）或更宽松任务采样。
