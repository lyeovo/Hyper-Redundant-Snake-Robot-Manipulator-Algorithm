# P0 可行性验证报告：失败域示范增强能否提升直出率与成功率

> 日期：2026-08-10 · 状态：**验证完成** · 配套：《云训练迁移指南.md》（云上大规模训练）

---

## 1. 验证目标

回答两个问题：
1. **"失败任务示范"能否提升模型直出率/成功率**（提前训练换取实时任务时间的前提）？
2. 具体用哪种数据形态最有效（**扰动变体** vs **目标对齐示范**）？

## 2. 验证流程（3 个实验）

```
① 失败收集: 300 任务评估当前部署闭环（C1_ft）
   → 263 成功(88%) / 37 失败
   → 巨型预算诊断(3 seed × 20000 样本 RRT*)：可解 11 / 疑似不可解 26
② 数据生成（2 种形态）:
   A. 扰动变体: 目标±0.15m 扰动 + q0/障碍扰动 → 200 条（可解率 47%）
   B. 目标对齐: 目标不动，仅 q0±0.3/障碍±0.03 → 280 条（可解率 81%）
③ 训练 + 验证:
   v2 = C1_ft + A(200 条)；v3 = C1_ft + B(280 条)
   同测试集(150 任务, rng(5)) + 失败例专项(11 可解例)
```

## 3. 结果

### 3.1 总体对比（150 任务，同测试集）

| 模型 | 成功率 | 直出率 | 末端 pos | 平均耗时 |
|---|---|---|---|---|
| C1_ft（基线） | 88.7%（133/150） | 52.7%（79） | 0.0134m | 6.5s |
| v2（扰动变体） | 88.0%（132） | **64.7%（97）** | 0.0142m | 7.8s |
| **v3（目标对齐）** | **90.0%（135）** | 58.7%（88） | **0.0119m** | **3.2s** |

### 3.2 失败例专项（11 个可解失败例救回率）

| 模型 | 救回 | 直出 |
|---|---|---|
| C1_ft | 7/11 | 5/11 |
| v2 | 7/11 | 5/11 |
| **v3** | **8/11** | 4/11 |

## 4. 结论

1. ✅ **路线可行（核心结论）**：**目标对齐示范**（失败任务本身，多 seed 巨型预算重解）微调后——
   - 成功率 88.7% → **90%**（150 任务）
   - 平均耗时 6.5s → **3.2s（减半）**——直出/回退组合更高效
   - 最难 11 例救回 7 → **8**
   - **提前训练确实能换实时性**（耗时减半 + 成功率提升）

2. ❌ **扰动变体无效**（v2）：直出率 +12%（52.7→64.7）但成功率不涨、失败例救回率不变——
   **目标 ±0.15m 扰动导致分布漂移**（变体分布中心 ≠ 原失败例）。**教训：失败域增强必须用原任务本身，不能扰动目标**。

3. ⚠️ **上限与瓶颈**：
   - 11 个可解失败例中仍 **3 个救不回**（对应 var1 失败例 1-4——生成示范时 MATLAB 3 次 Access violation 崩溃）
   - **26/300 任务（8.7%）疑似不可解**——训练永远救不了 → **必须叠加可解性分类器**（毫秒级拒绝）才能逼近 100%

## 5. 意外发现（重要）

1. **var1 崩溃 bug**：失败例 1-4 在 `method_rrtstar`/`optimizeTraj` 生成示范时触发 **MATLAB 原生崩溃（0xc0000005 Access violation）**——极端几何场景（目标邻域几乎被障碍覆盖）下的内存越界。**需单独诊断**（影响示范生成管线的鲁棒性）。
2. **可解性分布**：12% 失败中 70% 是"疑似不可解"——**当前成功率天花板**约 88-90%（对齐示范后），**突破天花板必须靠可解性分类 + 更强兜底**，而非更多训练数据。

## 6. 对云训练（后续大规模）的指导

| 项 | 建议 |
|---|---|
| 数据形态 | **只用目标对齐示范**（禁用目标扰动）；每失败例 40-100 条多 seed 重解 |
| 规模 | 对齐示范 1000-3000 条（当前 280 条已验证方向，规模放大收益待验） |
| 架构 | `--hidden 512` 大容量 + 全量基础数据防遗忘（`--init` 从 C1_ft，`--lr 1e-4`） |
| 验证口径 | 同测试集 150 任务 + 失败例专项 37 例（failures_20260810.mat）双指标 |
| 设备 | `train_cvae.py` 已 GPU 就绪（cuda/mps/cpu 自动），云上直接跑 |

## 7. 下一步（P1，未启动）

- **var1 崩溃诊断**：定位 method_rrtstar 极端场景内存越界
